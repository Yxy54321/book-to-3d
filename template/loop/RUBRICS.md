`LOOP.md` 与 `PLANNING.md` 引用本文件的章节号。本文件可以通过 `loop/AMENDMENTS.md` 收紧或细化，不能放松（宪法 C9）。凡写“本章”的地方，具体内容来自 P1 的规划产物。

## 1. 体验支柱（评分 1–5；下列为 1/3/5 的锚点）

| 支柱 | 1 | 3 | 5 |
|---|---|---|---|
| **E1 在场感** | 一个看不出年代和地点的 3D 房间 | 年代与地点对，但不知道自己是谁、为什么在这里 | 知道自己是谁、为什么在这里；那个地方那一年的尺度、光、声音都对 |
| **E2 动手与诚实因果** | 点击播放预定动画，输入不影响结果 | 动作有影响，但结果主要靠界面文字告知 | 核心动作驱动真实计算或真实记录；换一种输入，世界里看得见不同的结果 |
| **E3 理解** | 理解分 < 0.8 | 0.8–1.4 | ≥ 1.5，且多数答案引用自己的动作 |
| **E4 发现** | 先被告知，再去做 | 做完立刻被告知 | 体验者在解释出现之前就说出了领悟 |
| **E5 情绪与节奏** | 平铺直叙或拖沓；悲剧被煽情或被轻慢 | 有起伏但有拖沓段 | 情绪曲线清楚，主动/被动交替，克制处有力 |
| **E6 忠实** | 有虚构场面、捏造引语或错误技术说法 | 事实大体对，细节或出处标注有缺 | 事实、引文、归因、分寸都对；改编与史料都标注清楚 |
| **E7 视觉** | 构图乱、主体看不清、风格不一致 | 主体清楚，风格基本一致，大形或光有明显缺陷 | 构图引导视线，大形、光、材料符合选定风格的规格，与已批准参考图和同类测试场景一致 |
| **E8 可用性** | 卡住、死路、文字墙 | 能走通，但有超过15秒的困惑点 | 不需要教程墙就知道该做什么；文字在预算内；可键盘操作、有字幕 |
| **E9 技术** | 报错、掉帧严重 | 偶有卡顿 | 全部预算达标、无错误 |
| **E10 回响** | 结尾突然结束 | 有收尾，但看不出这一章在全书中的位置 | 结尾落得住；体验者知道这一章之前发生过什么、之后的故事往哪里去（只用正文已有的信息） |

## 2. 严重度

| 严重度 | 定义 | 例子 |
|---|---|---|
| **高** | 违反宪法或派生宪法；阻断完成；核心概念讲错或误导；骨架场景的核心动作是假的；严重不尊重 | 虚构正文没有的当面对峙；机制结果被写死；伤害性行为被做成玩法；默认路径无法走通 |
| **中** | 多数体验者会察觉并明显削弱某个支柱 | 困惑超过15秒；关键物件看不清；文字超预算；情绪节拍被破坏；关键镜头与全书风格不一致；帧率低于预算；时代明显穿帮 |
| **低** | 打磨级 | 次要物件材质略平；转场稍慢；某句译文生硬 |

## 3. 评审视角

### 3.0 通用提示词骨架（每个视角在此基础上加 3.x 的内容）

```
你是「{视角名}」。这是一次独立评审：你没有看过此前任何版本或任何评审意见。
评审对象：把 Cade Metz《Genius Makers》第 {N} 章 {TITLE} 做成可亲历 3D 体验的作品，当前版本（或当前规划/设计文档），范围：{scope}。
你只能使用当前目录 inbox/ 中的文件：{文件清单}。不要读取任何其他路径。
关注点：{3.x 关注点}
必须回答：{3.x 必答问题}
不归你管：{3.x 排除项}
输出：只输出一个 JSON，符合 review.schema.json。
- 每个 issue 必须引用证据：文件名 + 区域描述 / 日志行 / 文档章节 / 原书页码。
- 严重度按以下定义：{第2节}。
- 没把握的问题写低置信度，不要省略；确实没有问题就返回空列表，不要为显得有用而凑问题。
- 可以给修法建议，请优先考虑“去掉什么”的方案。
```

### 3.1 初见玩家

- **关注**：我知道自己是谁、在哪里、该做什么吗？哪里看不懂、哪里无聊、哪里让我想多待一会儿？
- **必答**：每个节拍用一句话说“我以为这里在发生什么”；指出最想跳过的一处和最难忘的一处。
- **不管**：史实细节、代码、风格是否符合圣经。

### 3.2 读过书的读者

- **关注**：这比读那几页多给了我什么？有没有歪曲正文的分寸？规划中“读者会带走什么”（种子第0节）有没有被保留？
- **必答**：每个场景写一句“体验给了阅读给不了的东西”，写不出就写“无”（每个“无”是一个中严重度 issue）。
- **不管**：性能、代码。

### 3.3 史实与技术审校

- **关注**：事实、年代、物件、引文、出处等级、归因措辞、种子第9节的易错点；机制实现是否真实（读 `app/src/sim/`、内容数据与 `mechanism-tests.md`），L1/L2 的技术说法是否准确，规模缩小与回放是否如实说明。
- **必答**：逐条核对本范围内的事实陈述与引文；指出时代穿帮；判断偏离路径测试是否真的证明了诚实因果。
- **不管**：好不好看、好不好玩。

### 3.4 美术指导

- **关注**：构图与视线引导、大形与尺度、光与发光层级、材料；是否符合 `STYLE_CONTROL.md` 的共用规则与选定风格的章节（见 `SELECTION.json`）；有已批准参考图时，实机渲染与参考图是否“同一画面意图”；与 `reference/test-rooms/` 中同类场景的一致性；第10节清单。评审对象是实机截图（审参考图时除外）。
- **必答**：为每个关键镜头给 1–5 分并说明最大的一处差距；指出“加细节无法解决、必须改大形”的问题；逐条指出任何不符合风格控制的地方（注明是哪一节）。
- **不管**：史实、文本。

### 3.5 交互与可用性

- **关注**：可供性、反馈、首次有效动作、死路、重复是否变成磨损、文字负担、键盘与字幕、探针指标。
- **必答**：每个节拍“玩家下一步该做什么”是否一眼可知；对照探针指标指出超预算项。
- **不管**：史实、风格。

### 3.6 叙事与情感导演

- **关注**：情绪曲线、主动/被动交替、转场、克制、身份是否在世界里成立、母题是否回响、结尾是否落得住。
- **必答**：用文字描述实际的情绪曲线，并与规划（种子第6节）或现行规格对比；指出最弱的一个转场。
- **不管**：代码、性能。

### 3.7 尊重与版权

- **关注**：宪法 C5–C7、C13–C15；`book/SENSITIVITY.md`；本章派生宪法逐条；真实人物（多数在世）的呈现；逐字引文预算；出处与许可；公司标志。
- **必答**：逐条检查派生宪法；列出所有逐字引文及其 lint 结果；P1 时检查敏感扫描是否覆盖了每一类。
- **不管**：好不好玩。

## 4. 比较者规程

```
你会看到同一体验（或同一文档）两个版本 A 与 B 的证据（相同相机、相同路径、相同裁切）。你不知道哪个版本更早，也不需要猜。
第一步：只看证据，给出整体偏好：A / B / 分不出，置信度：低 / 中 / 高。理由必须引用具体文件。
第二步：阅读下面的问题描述。对每个问题，分别说明它在 A 中和 B 中的状态：不存在 / 轻微 / 明显 / 无法判断，并引用证据。
第三步：列出只在其中一个版本里出现的问题（注明版本与严重度），尤其是高/中严重度的。
输出：只输出一个 JSON，符合 verdict.schema.json。
```

编排者把第二步换算为 `已解决 / 改善 / 无变化 / 变差 / 无法判断`：候选“不存在”且基线非“不存在”→已解决；候选比基线轻→改善；相同→无变化；更重→变差；任一侧“无法判断”→无法判断。

## 5. 盲测试玩员规程

### 5.1 提示词骨架

```
你是一位成年读者，没读过《Genius Makers》，对人工智能只有日常了解。你正在体验一个 3D 作品。
你只能通过命令 `play` 操作它（look / click x y / drag … / key … / type … / wheel … / wait …），每次动作后你会得到新的画面截图和屏幕上可见的文字。
不要读取任何文件，不要尝试打开源码或网页工具。像一个真人一样操作：看画面，猜哪里能点，试一试。

每一步先写一条记录：{"step":n,"see":"我看到…","think":"我以为…","intend":"我想…","action":"…"}
耐心规则：
- 画面 15 秒内没有新东西、或你不知道该做什么时，在 think 里写「无聊」或「困惑」并说明原因。
- 要读超过 3 行文字才知道下一步做什么时，写「文字太多」。
- 连续 3 次动作都没有看得见的变化时，写「卡住」，然后换一种尝试。
结束条件：出现结束画面；或在一个场景里用了 {场景步数上限} 步；或全程 {总步数上限} 步。

结束后回答第 6 节的问卷。回答时只依据你在这次体验里看到和做过的事。如果某个知识是你本来就知道、而不是体验告诉你的，必须标出「原本就知道」。
```

初始步数上限：单场景 120 步，全章 700 步（可由修正案调整）。

### 5.2 为什么要这样约束

AI 试玩员比真人更有耐心、会读完所有文字，而且对书中很多技术和人物本来就有了解（越往后的章节越明显）。所以：用耐心规则模拟真人的注意力；理解问题锚定在“这次体验里发生了什么”；原本就知道的内容单独标出、不计分。试玩结果只能作为人类体验的近似，报告里必须这样称呼（宪法 C8）。

## 6. 理解探针

### 6.1 问卷

1. 用第一人称讲讲你刚才经历了什么，不少于 5 句。
2. 理解问题：逐条使用 `design/learning-objectives.json` 中本次范围涉及的 `question`。
3. 哪个时刻你觉得自己“就在那里”？为什么？
4. 哪个时刻你觉得像在读文字或看幻灯片？
5. 有什么你想做但做不到的？
6. 哪里困惑、哪里无聊？（引用步骤号）
7. 你想不想继续体验这本书的其他部分？为什么？

### 6.2 评分（由一个新的标注会话完成，不由试玩员自评，也不由编排者打分）

| 分 | 条件 |
|---|---|
| 2 | 答案正确，并引用了自己在体验中的动作或所见 |
| 1 | 答案正确，但只引用屏幕文字或旁白 |
| 0 | 错误、未答、或标为「原本就知道」 |

- **理解分** = 各学习目标平均分。
- **发现率** = 标为 `discoverable_by_doing` 的学习目标中得 2 分的比例。
- 参考答案来自 `learning-objectives.json` 的 `reference_answer`。

## 7. 亲历感探针

- **施动比**：新的标注会话把问卷第1题拆成分句，统计“我 + 作用于世界物件的动作”的分句占比。P5 初始阈值 ≥ 0.5，之后只能上调。
- **亲历时刻提名**：问卷第3题。每个骨架场景至少被一位试玩员提名（P5 出口）。
- **比阅读多了什么**：读者视角（3.2）的必答项。
- **想做却做不到**：问卷第5题的每条都转成 issue 候选，由交互视角判断是“应当支持”还是“刻意的边界”（刻意的边界需在世界里给出理由）。

## 8. 自动探针与预算（初始值，只能收紧）

| 探针 | 测法 | 初始阈值 |
|---|---|---|
| 节拍文字量 | 默认层可见的界面文字 + 说明性世界文字（报纸标题等道具文字另计） | 中文 ≤ 60 字/节拍；英文原话 ≤ 25 词/节拍 |
| 道具文字可读 | 需阅读的世界内文字在节拍相机下的字高 | ≥ 14 px |
| 最长被动段 | 不需要输入且没有新信息的连续秒数 | ≤ 20 s（标为 passive 的节拍按其 `max_seconds`） |
| 首次可交互 | 进入场景到第一个可操作物件出现可供性提示 | ≤ 5 s |
| 首次有效动作 | 试玩员进入场景后到第一个有效动作的步数 | ≤ 3 步 |
| 输入反馈延迟 | 输入事件到目标物件第一次视觉变化 | p95 ≤ 100 ms |
| 帧率 | 真实 GPU、1440×900、各节拍相机 | 选定 archival/paper/editorial 时平均 ≥ 55，miniature ≥ 50；p5 ≥ 45 |
| 绘制开销 | `renderer.info` | 每场景 draw calls ≤ 250，三角面 ≤ 1.5M |
| 控制台错误 | 全部路径 | 0 |
| 关键物件可见 | 节拍相机下投影面积、遮挡率 | 面积 ≥ 1.5% 视口；遮挡 ≤ 30% |
| UI 遮挡 | 界面矩形与关键物件投影框重叠 | ≤ 10% |
| 文字对比度 | 界面文字 | ≥ 4.5:1 |
| 曝光 | 关键镜头线性亮度均值；过曝像素（≥250）比例，发光物本身除外 | 均值 0.25–0.65；过曝 ≤ 2% |
| 默认路径时长估算 | Σ演出时长 + Σ文字字数 ÷ 300字/分钟 + 动作数 × 1.5 s | 本章设定范围（PREFERENCES F7） |
| 猴子测试 | 随机输入 | 20 分钟 0 卡死 0 错误 |
| 逐字引文 | 归一化后（合并空白、统一弯引号、去行末连字符、拼接相邻页以覆盖跨页引文）在 `source/` 或已登记来源中逐字命中；含省略号或被插语打断的引文按段匹配，各段都命中且顺序一致 | 100% |
| 引文预算 | 单条英文 ≤ 50 词；产物中逐字引文合计 ≤ 600 词 | — |
| 出处字段 | 每条内容数据有 `provenance`（book/research/adaptation）与页码或来源 | 100% |
| 资源许可 | 每个字体、贴图、音频有许可记录 | 100% |
| 声音 | 提示表中的事件都触发；RMS 在设定区间；对白与关键声音有字幕 | 100% |
| 风格工具包 | 颜色、材料、光照、人物、UI 来自 `book-style-kit`；本章新增项在 style-extension 中有记录 | 100% |
| 只写不变层 | `tools/lint-style.mjs`：场景代码中没有颜色值、粗糙度、金属度、贴图路径、后期参数 | 0 处 |
| 角色覆盖 | 场景用到的每个材质角色在选定风格中都有映射 | 100% |
| 镜头参数 | `beats.json` 中每个节拍镜头的眼高、距离、视场角、俯仰在风格控制第4节范围内；滚转为 0 | 100% |
| 人物五官 | 每个人物有风格控制第5节的五官；无禁止项（瞳孔高光、睫毛、皱纹、牙齿、照片贴图） | 100% |
| 年代字体 | 年代带 A/B 场景中没有 `type.modern_sans` | 0 处 |

## 9. 机制真实性测试（通用要求）

本章的具体测试在 `design/mechanism-tests.md`（P1 写计划，P4/P5 实现为 `tests/mechanism/*`，永久回归）。每个有机制的章节至少覆盖：

| 类别 | 要求 |
|---|---|
| MT1 史实节奏 | 正文给出的数字（样本数、轮数、时长、比分等）作为校准目标；默认参数下多数随机种子落在目标附近（容差在计划中写明） |
| MT2 正确性 | 机制在它本该成功的任务上成功、在正文记载失败的地方真实失败（例如单层感知机做不出 XOR：对权重网格穷举，最高正确率为 3/4） |
| MT3 偏离输入 | 体验者给出不同或错误的输入时，机制产生相应不同的结果（例如标签教反，就学反） |
| MT4 可复现 | 同种子同结果 |
| MT5 界面一致 | 界面上的读数、物件状态与内部状态一致（浏览器测试同时读取二者比较） |
| MT6 规模与回放披露 | L1/L2 中存在缩小规模或回放的说明，且与实现一致 |
| MT7 不偷换机制 | 体验声称展示的机制就是实际运行的机制（例如声称是感知机规则，就不能暗中使用反向传播） |

无机制的章节：`mechanism-tests.md` 写“无机制”与理由，由史实与技术审校确认；本章的诚实因果改由偏离路径测试承担（体验者的选择被真实记录，并与正文中的历史结果并列呈现）。

## 10. 美术与时代检查清单

**来自风骇岛的教训**：整体泛白（颜色空间）；窗户或灯过曝成白板；所有发光物同样亮；物件悬空、没有接触阴影；互相穿插；Z-fighting；UV 拉伸；重复纹理明显；大形规整得像方块；用加小装饰掩盖大形问题；人物比例失调；世界内文字模糊。

**时代**：逐项对照本章 `design/era-checklist.md`（年份、光源与色温、物件、服装、字体与印刷物、技术设备、“绝不能出现”的东西）。

**全书一致**：对照 `book-style/STYLE_CONTROL.md`、`style.tokens.json`、`reference/approved/` 与 `reference/test-rooms/`；年代差异用年代带规则在选定风格内表现，而不是换一套风格。风格控制第9节的禁止事项不能出现。

**界面**：世界内反馈优先；界面采用选定风格的界面主题（风格控制第6.7、7节）；年代带 A/B 不出现扁平图标。
