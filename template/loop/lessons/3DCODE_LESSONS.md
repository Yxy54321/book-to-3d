# 3dcode 与风骇岛的经验（包内版）

这份文件把作者之前两个项目里验证过的做法提炼出来，让没有那两个项目的电脑也能直接用。来源：`3dcode/stormwreck-world`（风骇岛，Three.js 程序化叙事原型）的 `docs/director.md`、`art-direction.md`、`art-v3-review.md`、`player-agency.md`、`review.md`，以及 `3dcode/image-to-3dcode-harness-viewer-decoupled/README.md`（图像到 3D 代码的迭代 harness）。如果本机恰好有这两个项目，可以作为额外参考阅读，但不是必需的。

P0 时把与本章相关的条目抄进本章 `playbook/lessons.md`（标注“来自 3DCODE_LESSONS 第 N 条”）。

## 一、迭代与评审（来自 3dcode harness）

1. **接受版棘轮**：每轮只在“明确改善了目标问题、且没有高/中严重度回退、没有新问题、没有无法判断的视角”时更新接受版；拒绝、失败、证据不足都保留原接受版。**分数不决定接受**，比较判断决定接受。
2. **独立会话**：评审、比较、修复各用新会话，只给工作单指定的输入（原图、当前渲染、范围说明），不读其他 case、历史、聊天。
3. **先审后改**：review 输出必须带图像证据；从有效 review 的问题中选本轮目标，写成绑定源码与轮次的 scope，下一轮可以换目标。
4. **冻结身份清单**：对象 ID、部件、未决条目在迭代中冻结；非目标对象、共享 helper、相机、布局默认受保护。不能偷偷放宽范围。
5. **成对比较**：比较会话看“原图 / 上一接受版 / 候选”三组图，按视角逐一判定；任何高/中回退或 uncertain 都阻止接受。
6. **一次修复**：候选审计失败时最多一次独立修复，只给它实际错误。
7. **预算与停止**：会话数、轮数、单会话时长都有上限；连续拒绝达到阈值就停下重新诊断。上限是安全界限，不是质量达标条件。

## 二、对象与运行时（来自风骇岛）

8. **稳定对象外壳**：每个可交互物件一个独立 Group，保留 ID、选中状态与世界变换；只替换需要改变的几何/材质/特效子树。共享材质不能被一个物件的变色污染（每个物件独立材质实例）。
9. **局部更新**：一次操作只更新真正改变的对象集合，并能证明无关对象实例保持不变（风骇岛岩石热替换时 26 个其他对象外壳不变）。
10. **builder 独立文件**：物件造型写在独立 builder 模块里，可单独修改、热替换、失败隔离；替换前做几何/预算/版本检查，失败回滚并释放资源。
11. **诚实反馈的四种结果**：`executed`（真实执行，含不利结果）、`blocked_by_world`（世界条件不满足，说明原因）、`needs_clarification`（有歧义，列出候选）、`needs_extension`（意图可理解但能力未实现，说明缺哪一环）。不能把未实现的动作降级成“观察”后宣布完成，也不能只播特效不改状态。
12. **坐标合同**：逻辑层与美术层的坐标必须一致，否则首次更新会“跳位”；用测试锁定关键物件坐标。
13. **动画与回滚**：快速重置或撤销时必须清空进行中的补间动画，否则旧动画会把模型拉回旧位置。

## 三、美术与渲染（来自风骇岛）

14. **颜色空间**：Three.js r128 不会自动把十六进制底色转为线性值，首次集成画面整体泛白；对材质底色、自发光、顶点色统一做 sRGB→线性转换，输出用 sRGB + ACES。新版 Three.js 要正确设置 ColorManagement 与输出色彩空间。
15. **先大形，后细节**：V3 审核的结论——大形体与构图有差距时，继续加小装饰或提高纹理频率无法消除差距；应先重做英雄级大形（断崖、洞口、建筑轮廓），再统一细节。
16. **发光层级**：发光集中在灯芯/光源内核，窗格要可辨；不能让所有发光物同样亮，窗户不能过曝成白板。
17. **接地与穿插**：建筑必须接地，落地物件要有接触阴影；用测试检查屋面与塔窗等穿插（风骇岛钟楼修复：检查拱窗空间内屋瓦顶点为 0）。
18. **视线封闭**：门洞、墙体之间不能留贯穿空隙；用多角度视线覆盖测试证明（风骇岛洞口封闭）。
19. **概念板是目标，不是截图**：设定图只作为制作目标，任何报告不得把设定图当实机效果；剩余差距写进审核文档。
20. **贴图与几何分工**：生成的底色贴图提供材料颗粒，不在单块石材上画整面砌体；接缝、瓦片压叠、木板断裂由几何表达。底色按线性平均亮度归一后再乘设计色，避免重复变暗。
21. **性能**：静态环境按材质签名合批，重复物件用 InstancedMesh，可交互根节点保持独立；粒子合并为一个 Points。离线构建统计三角面与绘制调用；帧率只在真实 GPU（如 Apple M 系列 + ANGLE Metal）上测才算数，软件光栅（SwiftShader）明显更慢，只做功能验证。

## 四、验证与记录（来自风骇岛）

22. **技术通过与美术通过分开记录**：headless 语义测试通过不等于画面通过；浏览器实机截图审查单独进行。
23. **按版本保存 QA**：每次美术大改前做完整备份并生成 SHA-256 清单；截图与报告按版本放在 `qa/vN/`。
24. **验收场景写成可执行测试**：例如“移走配重门重新关闭”“撤销后状态、模型、任务条件一致”“未知输入不改变世界”。
25. **交付边界写清楚**：原型做到了什么、没做到什么、哪些是单次观测（例如某次规划耗时）而不是保证。
